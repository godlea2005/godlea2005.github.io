# 项目过程日志

## 2026-08-09 — 首版基线

- 目标：为文昊搭建 React + Vite 个人网站，优先展示作品，兼容后续内容与服务端扩展。
- 视觉决策：采用原创的「信号档案」系统；吸收参考站的状态化信息层级与地图式内容组织，不复刻其素材、代码或界面。
- 版式决策：桌面最大版心 1200px；移动端固定 16px 页面边距；深浅色均作为一等模式实现。
- 数据决策：页面从 `src/content/site.ts` 读取演示数据，未来由 API/CMS 替换该适配层。
- 待办：用真实案例、头像、联系地址和部署参数替换演示内容。

## 2026-08-10 — 首版实现与验证

- 已实现：React + Vite 单页前端、原创信号档案视觉、精选作品、能力闭环、洞察入口、移动菜单及主题持久化。
- 已通过：`npm run build`（TypeScript 与 Vite 生产构建）。
- 浏览器检查：首页语义结构、桌面布局与本地预览可用；移除了外部字体依赖并补充站点图标，避免第三方资源失败影响页面体验。
- 修正：首次访问固定为深色模式；用户手动切换后才持久化该选择。
- 后续：替换演示案例和联系邮箱；接入后端时仅需实现内容适配层与环境变量中的服务地址。

## 2026-08-10 — 数字工作室重构决策

- 复盘：首版仅提取了参考站的公告和分区索引，整体仍是机构式作品集，未达到“个人数字空间”的视觉与叙事效果。
- 决策：保留技术基础，重构为「文昊的数字工作室」；以个人状态场景、数字地图、作品档案和实验记录替代传统 hero + 卡片流。
- 原则：参考站的信息组织、状态感与探索节奏，不复制其品牌、角色、插画、文案、代码或布局细节。
- 已实现：首页重构为个人状态场景、工作台插画、站点动态、数字地图、项目档案与实验记录；内容继续集中于静态适配层，便于后续接 CMS/API。
- 已通过：`npm run build`（TypeScript 与 Vite 生产构建）。
- 验证限制：本轮 Playwright 启动 Chrome 时被运行环境关闭，未能完成自动化截图；本地 Vite 预览仍可通过 `http://127.0.0.1:5173/` 访问，下一轮优先补做桌面与移动端自动化检查。

## 2026-08-11 — 音乐页重构

- 参考页走查：确认音乐页核心为全屏沉浸场景、中央可视化、漂浮歌词、底部控制台和侧边歌单抽屉，而不是普通播放器卡片。
- 已实现：独立 `#music` 路由、曲目切换、播放状态、模拟进度、音量、三种循环模式、歌词显隐、歌单抽屉和响应式布局。
- 音源边界：未复制或接入参考站曲目；当前使用原创演示元数据，后续仅接入用户拥有授权的音频文件或音乐 API。
- 验证：TypeScript/Vite 生产构建通过；Playwright 成功识别音乐页全部播放器控件和歌单结构。后续交互复测时浏览器会话被运行环境关闭。
