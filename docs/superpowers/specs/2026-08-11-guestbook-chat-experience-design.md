# 文昊留言页设计规范

## 目标

为个人网站新增独立留言页，参考 `tblog.mmzhiku.xyz/guestbook/` 的聊天室式视觉和交互逻辑，但使用文昊自己的品牌、文案、数据和代码。首版必须可以本地运行、提交留言、回复、复制并刷新后保留；后续接入服务器和数据库时不重写 UI。

## 路由与入口

- 页面使用现有 Hash 导航，地址为 `#guestbook`。
- 顶部导航“联系我 → 留言”从邮件链接改为 `#guestbook`。
- 页面保留全站顶部导航、深浅主题和全局音乐 Dock。
- 从留言页返回主页、进入音乐页时，留言草稿和播放器状态均不丢失。

## 页面结构

### 顶部状态区

- 版心沿用网站的精确桌面宽度。
- 显示“留言板”、留言数量、最近同步时间和手动刷新按钮。
- 下方为可关闭公告条，包含“留言规则”和“留言需要审核”两项状态。

### 消息区域

- 使用聊天室式时间流，而不是传统评论卡片列表。
- 消息按日期分组；普通访客留言靠左，站长示例回复靠右。
- 每条消息包含头像、昵称、时间、正文、回复与复制操作，以及浏览器/系统等弱化元信息。
- 回复时在正文上方显示被回复消息的紧凑引用。
- 内容只按纯文本渲染，不使用 `dangerouslySetInnerHTML`。
- 首次数据为空时载入少量文昊站点风格的演示留言。

### 输入区

- 桌面端固定在留言区域底部，移动端位于安全区内。
- 支持 300 字文本、表情选择、图片选择入口、字符计数、游客资料和发送按钮。
- 游客资料包含昵称、邮箱和个人网站；昵称必填，邮箱和网站可选。
- 首版图片限制为单张、小于 600 KB，并以 Data URL 存入本地适配器；未来 API 版本改为对象存储 URL。
- 空内容、超长内容、缺少昵称或不支持的图片必须给出明确错误提示。

### 规则弹窗

- 首次进入显示简洁的留言规则弹窗。
- 规则包含友善交流、禁止违法侵权、骚扰、广告、诈骗及泄露隐私等约束。
- 用户确认后在当前浏览器记录状态；公告中的“留言规则”可以再次打开。

## 视觉

- 深色模式以黑灰背景、低对比边线和青绿色状态光为主；浅色模式提供完整对应色，不是简单反色。
- 消息气泡克制、圆角较小，站长消息使用带轻微青色倾向的独立表面色。
- 页面避免模板化评论组件外观，保留现有网站的细线、坐标、编号和信号状态语言。
- 桌面端消息区拥有充足横向留白；移动端头像缩小、气泡占满可用宽度，所有按钮满足触控尺寸。

## 数据架构

### 类型

`GuestbookMessage` 包含：

- `id`
- `author`
- `emailHash` 或本地头像种子
- `website`
- `content`
- `image`
- `createdAt`
- `replyTo`
- `isOwner`
- `status`
- `clientMeta`

### 适配器

定义 `GuestbookRepository`：

- `list(): Promise<GuestbookMessage[]>`
- `create(input): Promise<GuestbookMessage>`
- `refresh(): Promise<GuestbookMessage[]>`

首版 `LocalGuestbookRepository` 使用版本化 `localStorage` 键保存数据。未来 `ApiGuestbookRepository` 读取 `VITE_GUESTBOOK_API_URL`，组件无需感知存储方式。

### 后端准备

- 数据状态预留 `pending / approved / rejected`。
- 服务端版本必须实现内容审核、速率限制、输入清洗、图片对象存储和管理员鉴权。
- 前端不保存后台密钥，不信任客户端传入的 `isOwner` 和设备信息。

## 组件边界

- `GuestbookPage`：页面状态与区域编排。
- `GuestbookHeader`：数量、同步状态、公告入口。
- `MessageTimeline`：日期分组和消息列表。
- `MessageBubble`：单条消息、引用、复制和回复。
- `GuestbookComposer`：草稿、表情、图片和发送。
- `GuestIdentityPanel`：游客资料。
- `GuestbookRulesDialog`：规则弹窗。
- `guestbookRepository`：本地与未来 API 数据隔离层。

## 状态与错误

- 初始化显示连接/加载状态。
- 本地存储不可用时退化为当前会话内存存储，并显示非阻塞提示。
- 提交期间禁用重复发送；成功后清空正文和图片，保留游客资料。
- 复制失败时提示用户手动复制。
- 图片读取或存储超限时不影响纯文本草稿。

## 响应式

- `>= 901px`：完整聊天室布局，消息气泡最大宽度约 54%，输入区两层控制。
- `<= 900px`：消息气泡最大宽度约 82%，公告条横向滚动，输入区紧凑重排。
- `<= 520px`：隐藏非必要设备元信息，游客资料使用底部面板，规则弹窗占据安全宽度。

## 验收

- `#guestbook` 可直接访问并可从导航进入。
- 深色、浅色、1440×900 和 390×844 均无横向溢出。
- 可编辑游客资料、提交文字、选择表情、附加合规图片、回复和复制留言。
- 刷新页面后本地留言仍存在；清空站点本地存储后恢复演示数据。
- 规则弹窗、公告关闭和草稿状态符合预期。
- 音乐播放器在留言页保持连续播放。
- `npm run build` 和 Playwright 核心交互检查通过。

## 不在首版范围

- 真实多人同步、账号登录、管理后台、服务端审核、IP 定位和对象存储上传。
- 这些能力通过预留 Repository 和环境变量在上线阶段接入。
