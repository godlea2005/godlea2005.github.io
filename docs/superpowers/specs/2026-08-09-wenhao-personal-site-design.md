# 文昊个人网站：首版设计说明

## 目标

建立一个可持续扩展的个人站首版，优先展示作品，同时让 AI 设计、电商运营和前端实现三种能力形成一个完整的工作方法。页面是个人工作台，不是简历模板；后续可接入内容管理、数据库、访问统计和服务器部署。

## 设计方向

采用「信号档案」方向：参考站的状态感、信息地图、滚动公告和分区索引逻辑，但不复制其界面、动画、内容或品牌。

- 默认深色，支持浅色模式并记住用户选择。
- 使用冷黑、雾灰和单一电蓝作为强调色，避免高饱和霓虹与装饰性 3D。
- 桌面版版心最大宽度 1200px、水平内边距 32px；移动版宽度为视口减 32px。所有区块与导航使用同一对齐线。
- 作品作为首屏下方的第一主要内容；文章和方法论作为可扩展的第二层。

## 信息架构

单页锚点导航，首版包含：

1. 顶部导航：文昊、作品、洞察、关于、主题切换。
2. 状态首屏：当前身份、简短主张、可用状态、时间与专业标签。
3. 信号条：滚动显示「作品更新」「能力范围」「开放合作」三条站点信息。
4. 精选作品：三个带明确角色、行业和结果的项目卡片。首版使用原创的演示数据，数据从独立内容文件读取，替换真实项目无需改 UI。
5. 能力地图：把三种身份解释为发现机会、构建体验、实现交付的闭环。
6. 洞察：三个方法/文章入口，作为未来 CMS 内容列表的前端协议。
7. 联系页脚：邮箱占位和技术状态说明。

## 技术设计

- React 18 + Vite + TypeScript。
- 无重型 UI 库；以原生 CSS 变量、Grid、`clamp()` 与可访问的语义化元素实现。
- `src/content/site.ts` 为唯一的静态内容适配层；未来可替换为 REST/GraphQL/CMS 查询，而页面组件保持不变。
- `src/lib/theme.ts` 处理主题持久化；默认遵循系统主题，用户切换后写入 `localStorage`。
- `.env.example` 明确预留 `VITE_API_BASE_URL`、`VITE_CONTACT_ENDPOINT` 和 `VITE_ANALYTICS_ID`，不提交任何密钥。

## 交互与状态

- 主题按钮支持键盘访问，更新 `aria-label`。
- 导航在窄屏折叠为可展开菜单；点击链接自动收起。
- 作品卡片在键盘聚焦时显示同等视觉状态，链接使用可访问文本。
- 无 JavaScript 时内容仍保持可阅读；动效尊重 `prefers-reduced-motion`。

## 质量与验证

- 运行 Vite 构建和类型检查。
- 使用 Playwright 验证首页桌面与移动视口、主题切换和移动导航。
- 维护 `docs/project-log.md`：按时间记录决策、变更、验证结果与后续事项。

## 不在首版范围

- 登录、后台管理、真实数据库、真实表单投递、文章详情页和多语言。
- 这些不阻碍未来上线：内容模型、环境变量和 URL 层已为它们留出稳定边界。
