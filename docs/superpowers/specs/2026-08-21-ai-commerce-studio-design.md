# AI 电商设计工作台设计规格

## 1. 产品目标

在 `geniusli.cn` 内新增真正可使用的 AI 电商设计工作台，把文昊的个人网站从视觉实验与作品展示，升级为“个人品牌 + 专业案例 + 在线 AI 工具”。工具面向跨境俄罗斯市场与国内电商市场，根据用户提供的产品资料生成主图创意、详情页结构、画面文案和可直接复制的 AI 作图提示词。

首版不直接生成商品图片，不接在线支付。首版必须完成从登录、录入、分析、扣次、查看结果到历史管理的完整闭环。

## 2. 首发市场与平台

首发仅覆盖四个平台，优先做深平台差异，而不是输出通用电商模板：

- 俄罗斯：Ozon、Wildberries。
- 国内：抖音电商、淘宝/天猫。

每个平台拥有独立策略预设，包括内容节奏、画面信息密度、推荐比例、文案语气、用户关注点与常见合规提醒。俄罗斯平台允许用户输入中文资料，结果同时输出俄文画面文案和中文解释。

## 3. 网站信息架构调整

### 3.1 首页定位

首页首屏继续保留现有动态视觉，但核心信息改为：

> 为俄罗斯与国内电商市场提供 AI 商品视觉策略、主图构思、详情页分镜和可执行作图提示词。

首页新增：

- AI 电商设计主入口与“免费分析一个产品”按钮。
- Ozon、Wildberries、抖音、淘宝/天猫平台标识。
- 三步使用流程演示。
- 俄罗斯市场本地化能力说明。
- 示例结果或真实案例区域。
- 登录后的剩余次数入口。

音乐、实验记录等个人内容保留，但降低为次要层级，不抢占核心转化路径。

### 3.2 导航

桌面与移动端导航增加“AI 电商设计”主入口。工具页面、案例、留言和音乐继续复用现有悬浮导航、主题系统与响应式规则。

### 3.3 工具路由

首版在现有 React 单页应用内增加独立工具页面，推荐使用 `#ai-commerce`，保持与当前 `#music`、`#guestbook` 的静态 Pages 路由方式一致，避免 GitHub Pages 刷新回退问题。未来迁移到支持服务端路由的部署平台时可平滑改为 `/ai-commerce`。

## 4. 用户与权限

### 4.1 登录

- 游客可以浏览首页、案例和工具介绍，但不能提交 AI 分析。
- GitHub 或 Google 登录后可以使用工作台。
- 新用户默认获得 3 次体验额度，具体数值由站长后台配置。
- 继续使用现有 Supabase Auth，不建立第二套用户系统。

### 4.2 次数规则

- 一次成功的完整分析扣除 1 次。
- AI 调用失败、超时、结果结构验证失败或图片读取失败不扣次数；如果已预扣则自动退款。
- 同一个请求使用幂等键，刷新或重复点击不会重复扣次。
- 用户不能直接更新自己的额度。
- 次数变化全部写入不可覆盖的积分流水。

### 4.3 站长权限

建立通用 `site_admins` 权限，不把全站后台长期绑定在 `guestbook_admins`。迁移时把现有站长账号加入通用管理员表。

站长后台支持：

- 查看用户、注册时间、登录方式、剩余次数和累计用量。
- 增加、减少或直接设置次数，例如 `999`。
- 设置或取消不限次数。
- 查看生成任务、失败原因与积分流水。
- 人工退款。
- 禁用或恢复用户。
- 修改新用户赠送次数、每日限额与单次图片数量。
- 查看存储使用量与清理记录。

所有后台写操作由数据库函数或 Edge Function 校验管理员身份，不能依赖前端隐藏按钮。

## 5. 产品录入

### 5.1 快速模式

- 上传 1–6 张产品图。
- 填写产品名称。
- 选择市场与平台。
- AI 从图片和少量文本中识别品类、外观、材质线索与潜在卖点。

### 5.2 专业模式

在快速模式基础上增加：

- 产品品类与规格参数。
- 价格区间。
- 核心卖点。
- 目标人群。
- 品牌调性。
- 竞品或参考链接。
- 禁用词与不得改变的产品细节。
- 期望风格与补充说明。

两种模式都允许部分字段为空。AI 必须区分“用户明确提供的信息”和“模型推测”，推测项在结果中标记为待确认，禁止虚构尺寸、材质、认证、功效或性能参数。

### 5.3 上传约束

- 单个项目最多 6 张图。
- 接受 JPEG、PNG、WebP。
- 首版单图上限建议 8 MB，上传前在浏览器压缩预览副本，服务端再次校验 MIME 与文件头。
- 用户必须确认拥有图片使用权，并同意不得上传违法或无权使用的素材。

## 6. AI 输出结构

每次分析返回固定结构的 JSON，由结果页面分别渲染：

1. 产品摘要与信息可信度。
2. 目标用户与购买动机。
3. 卖点优先级及理由。
4. 平台适配策略。
5. 三套主图创意方向。
6. 每套主图的构图、背景、色彩、光线、道具、文案位置和视觉重点。
7. 8–12 屏详情页分镜，包含每屏目的、画面内容、文案和衔接逻辑。
8. 中文或俄文画面文案；俄文同时附中文解释。
9. 每套创意的完整 AI 作图提示词。
10. 负面提示词。
11. 推荐尺寸、比例与安全区。
12. 商品主体保真要求。
13. 平台合规与待确认事项。

用户可以：

- 一键复制单条提示词。
- 复制整套方案。
- 切换不同主图方向。
- 基于原项目重新生成。
- 保存项目名称和备注。
- 删除项目。

首版导出以复制和打印友好页面为主，暂不开发复杂 PDF 排版系统。

## 7. AI 服务架构

### 7.1 调用路径

浏览器不得直接持有 AI 服务密钥。调用链为：

`React 工作台 → Supabase Edge Function → 多模态 AI 服务 → 结构校验 → PostgreSQL → React 结果页`

Edge Function 负责：

- 校验登录身份、账号状态、每日限额和剩余次数。
- 获取用户私有产品图的临时访问地址。
- 读取平台策略预设。
- 组合系统提示与产品资料。
- 调用支持图像理解和结构化输出的模型。
- 校验返回 JSON。
- 成功扣次或失败退款。
- 写入生成记录、耗时和模型用量。

AI 层使用内部适配接口，首版只接一个默认模型，但数据结构不绑定具体厂商，未来可替换或增加模型。

### 7.2 请求状态

任务状态包括：

- `draft`：产品资料尚未提交。
- `queued`：已校验并等待处理。
- `processing`：AI 正在分析。
- `completed`：结果已保存。
- `failed`：分析失败且已退款。
- `cancelled`：用户或站长取消。

结果页面轮询任务状态；未来如迁移到实时任务系统，可替换为 Supabase Realtime，不改变页面数据结构。

## 8. 数据模型

建议新增：

- `site_admins`：全站管理员。
- `user_entitlements`：剩余次数、无限额度、禁用状态和每日限制。
- `credit_ledger`：赠送、消耗、退款、站长调整流水。
- `commerce_projects`：用户产品项目、平台、模式和输入资料。
- `commerce_project_assets`：私有图片路径、大小、到期时间和清理状态。
- `commerce_generations`：任务状态、结构化结果、模型、用量与错误信息。
- `platform_presets`：四个平台的可维护策略配置。
- `app_settings`：新用户赠送次数、图片上限、存储软上限等全局设置。
- `cleanup_runs`：自动清理执行记录。

所有用户数据启用 RLS。普通用户只能读取和管理自己的项目、资源和生成结果；管理员后台通过安全函数获取必要字段。

## 9. 图片隐私与清理

- 产品图片存入 Supabase 私有 Storage，不生成长期公开地址。
- 只有上传者本人和站长安全流程可以访问。
- 图片默认在上传后 7 天到期，文字方案和提示词继续保存。
- 用户主动删除项目时立即进入图片删除流程。
- 正在上传、排队或分析中的图片不得清理。
- 用户可将重要项目标记为锁定；首版锁定只阻止软上限提前清理，不改变 7 天默认到期规则，若以后需要长期保存必须单独设计套餐与授权。

### 9.1 定时清理

每日定时任务：

1. 删除已超过 `expires_at` 的图片。
2. 更新数据库资源状态与已用字节。
3. 写入 `cleanup_runs`。

### 9.2 存储软上限

系统维护可配置的 `storage_soft_limit_bytes`。当已统计的有效资源大小达到软上限时，额外执行提前清理：

1. 过滤掉正在处理与已锁定资源。
2. 按 `created_at` 从早到晚排序。
3. 删除最早上传的资源，直到回落到目标水位。
4. 保留文字方案，并在项目中显示“原始图片已自动清理”。

Supabase 实际套餐容量仍由控制台监控；应用软上限应设置在真实容量以下，避免等到存储完全写满才清理。

## 10. 管理后台界面

后台不出现在普通导航中，仅管理员登录后显示入口。首版包含四个标签：

- 概览：用户数、今日生成、失败率、额度消耗和存储量。
- 用户：搜索用户、调整次数、无限额度、禁用状态。
- 任务：查看任务状态、错误、耗时、模型和退款状态。
- 设置：新用户额度、每日限额、图片数量和存储软上限。

后台不默认展示用户产品图片缩略图，减少未上市产品泄露风险。需要排查时由管理员显式进入授权查看流程，并记录审计日志。

## 11. 异常与安全

- AI 密钥只存放在 Supabase Edge Function Secrets。
- 图片和文本输入执行类型、大小、长度和危险内容校验。
- 同一用户、IP 和设备设置合理速率限制。
- 请求使用幂等键，防止重复扣次。
- AI 返回结果必须经过结构校验，不合格时自动重试一次，仍失败则退款。
- 项目删除、额度调整、用户禁用和管理员查看敏感资源写入审计记录。
- 前端不得信任传入的用户 ID、剩余次数或管理员标记。
- 管理员不能读取 OAuth Secret 或 AI Secret。

## 12. 响应式与体验

- PC 使用左右分栏的产品录入与分析预览。
- 手机端使用分步表单，固定底部主操作区不得遮挡输入框。
- 上传、分析和结果页都提供明确的进度、失败原因和恢复操作。
- 用户离开页面后任务继续运行；返回历史记录可查看完成结果。
- 支持深浅模式，视觉延续现有克制、深色、科技感方向。
- 对减少动态效果偏好的用户关闭非必要动画。

## 13. 首版实施边界

首版包含：

- 首页定位与入口调整。
- AI 电商设计工具页。
- GitHub/Google 登录与 3 次默认额度。
- 快速/专业双模式录入。
- 私有图片上传。
- 四个平台策略。
- 多模态 AI 分析和结构化结果。
- 结果复制、保存、重试、历史和删除。
- 站长用户/次数/任务/设置后台。
- 7 天定时清理与存储软上限清理。
- 桌面和手机端验证。

首版不包含：

- AI 直接出图。
- 在线支付与充值。
- 团队和子账号。
- 长期图片存储套餐。
- 多模型手动选择。
- 复杂 PDF 或 PSD 导出。

## 14. 验收标准

- 未登录用户不能创建任务，登录后可看到准确额度。
- 新用户只获得一次可审计的默认赠送额度。
- 成功任务恰好扣 1 次，失败任务最终不扣次数。
- 站长可将朋友的额度设置为 `999` 或无限，并能看到对应流水。
- 普通用户无法读取或修改其他用户项目、图片、结果和额度。
- 四个平台输出包含可识别的平台差异。
- 俄罗斯平台结果包含俄文画面文案和中文解释。
- 结果满足固定结构，提示词可单条和整套复制。
- 超过 7 天的产品图片会清理，文字方案仍可查看。
- 达到存储软上限时按最早上传顺序清理合格资源。
- 首页、工作台、历史和后台在桌面及 390px 手机宽度无横向溢出。
- 生产构建通过，关键流程无应用控制台错误。
