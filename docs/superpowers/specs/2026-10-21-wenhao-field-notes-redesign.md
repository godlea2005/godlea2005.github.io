# WENHAO Field Notes 整站重构设计

## 目标

把现有以 AI 电商为中心、内容较浅的展示页，重构成一个有个人辨识度、值得持续阅读的文昊个人博客。网站需要同时容纳文章、作品、视觉随记、AI 电商实验室、工具导航、音乐和留言，但首页的第一身份始终是“文昊的个人编辑型博客”。

参考站只用于提炼信息层级、导航反馈、内容密度和个人氛围，不复制其文字、素材、构图或组件外观。最终差异化来自紫粉动态波场、WENHAO 粒子字、原创视觉素材、编辑型网格和文昊自己的内容结构。

## 设计原则

1. **内容先于效果。** 所有动画都必须帮助识别层级或说明可交互性，不做无目的展示。
2. **个人博客优先。** AI 电商是一个重点实验室入口，不是整站主题。
3. **动静交替。** 首屏和精选作品承担动效；文章索引与正文保持稳定、易读。
4. **原创而非复刻。** 不使用参考站的图片、文案、品牌元素或一比一布局。
5. **移动端不是缩小版。** 触摸设备取消目标光标和大幅倾斜效果，导航、内容墙和播放器使用适合单列阅读的交互。
6. **无效果也完整。** 关闭 JavaScript 动效、开启低动态偏好或 WebGL 失败时，标题、导航、卡片和所有正文仍然可访问。

## 整体视觉方向

方向命名为 **WENHAO FIELD NOTES / 文昊现场笔记**。

- 主色使用墨黑、纸白、雾紫和低饱和酸绿；紫粉只在动态波场和少量状态反馈中出现。
- 中文使用有力量的黑体标题与舒展的正文排版，英文标签和时间使用等宽字体。
- 页面由大留白、紧凑索引、少量沉浸式图像段落交替组成，避免当前连续说明文字和线框卡片带来的“产品说明书”感。
- 深浅主题共享相同层级；浅色主题是暖纸张感，深色主题是墨黑编辑室，不是简单反色。
- 原创位图只用于精选作品和视觉随记。首页动态背景、网格、光标、图标与装饰仍由代码生成，保证清晰度和性能。

## 信息架构

### 全局导航

桌面端使用原创实现的 Card Nav：默认是紧凑的浮动胶囊，点击或键盘展开后显示三组卡片。

- **阅读**：文章、现场笔记、归档
- **探索**：作品、AI 电商实验室、工具导航
- **连接**：留言、音乐、关于与联系

品牌按钮、搜索和主题切换独立保留。移动端改成全宽抽屉式目录，不模拟桌面卡片展开。导航必须支持 Esc 关闭、焦点回归、方向明确的当前页状态和至少 44px 的触摸目标。

### 首页顺序

1. **个人开场 / Hero**
   - 全屏 Gradient Waves 铺底，不放进有边框的容器。
   - WENHAO 使用 Particle Text，只在首次进入时形成；低动态和移动端直接显示静态字标。
   - “博客”作为稳定中文锚点，不参与粒子分散。
   - Text Type 轮换三条短身份句：“记录设计与技术的现场”“把想法做成看得见的作品”“在商业与创作之间持续实践”。完成一轮后停在第一条，避免长期干扰。
   - 主操作为“开始阅读”，次操作为“查看作品”；AI 电商放入探索入口而非首要按钮。

2. **本期精选 / Featured Notes**
   - 一篇主文章加两篇次文章，显示真实标题、摘要、日期、阅读时长和标签。
   - 卡片可进入真实文章详情，不再链接回当前区块。

3. **精选实践 / Selected Work**
   - 1–3 个真实案例使用 Tilted Card；倾斜限制在轻微角度，阴影和高光克制。
   - 每个案例有明确问题、角色、方法与结果，进入独立详情页。

4. **AI 电商实验室 / Commerce Lab**
   - 作为一个横向专题区，解释“产品资料 → 市场判断 → 主图/详情页方案”的能力。
   - 保留 Ozon、Wildberries、抖音、淘宝/天猫，但不在首页展开完整产品演示。
   - 一个明确入口进入现有工作台；工作台功能与数据库逻辑不重写。

5. **视觉随记 / Visual Notes**
   - 使用 Masonry 展示原创图像、短句、界面实验和生活观察。
   - 首版使用 6 个条目、三种比例；点击打开可访问的详情浮层，支持 Esc 与焦点回归。
   - 原创图像不包含参考站人物、场景或构图，不在图内生成文字。

6. **文章索引 / Writing Index**
   - 按日期展示完整文章列表，支持标签筛选。
   - 首页最多显示最近 6 篇并提供“查看全部”；首版 3 篇内容全部出现。

7. **关于与联系 / About**
   - 简洁说明文昊的三个工作视角和当前状态，连接留言、邮箱和合作入口。
   - 页脚保留 WENHAO 和建站信息，但去掉没有实际含义的占位式口号。

## 内容与页面模型

新增集中式内容模型，文章、案例和视觉随记从数据渲染，不把文案散落在组件内。

```ts
type ArticleBlock =
  | { type: "paragraph"; text: string }
  | { type: "heading"; text: string }
  | { type: "quote"; text: string }
  | { type: "list"; items: string[] }

type Article = {
  slug: string
  title: string
  excerpt: string
  date: string
  readingMinutes: number
  tags: string[]
  featured: boolean
  body: ArticleBlock[]
}

type Project = {
  slug: string
  title: string
  summary: string
  role: string
  period: string
  tags: string[]
  cover: string
  challenge: string
  process: string[]
  outcome: string
}

type VisualNote = {
  id: string
  image: string
  alt: string
  caption: string
  date: string
  ratio: "portrait" | "landscape" | "square"
}
```

首版提供 3 篇完整文章、3 个案例和 6 条视觉随记。内容可以是已存在主题的扩写，但不得伪造客户、商业成绩或合作品牌。案例中的演示内容必须明确标识为个人实验或演示。

Hash 路由继续沿用现有架构，新增：

- `#writing`：文章索引
- `#article/<slug>`：文章详情
- `#work`：作品索引
- `#project/<slug>`：案例详情

现有 `#ai-commerce`、`#tools`、`#guestbook`、`#music` 和管理页面保持可用。

## 组件与动效分配

- **Card Nav**：只用于全局导航；原创实现，不引入 React Bits 品牌元素。
- **Target Cursor**：桌面精细指针设备上用于导航卡、精选文章、精选作品和工具卡；普通正文链接使用系统光标。
- **Text Type**：只用于 Hero 的一行身份短句；静态文本始终存在于可访问树中。
- **Tilted Card**：只用于精选作品，最大倾角 6 度；键盘聚焦不依赖倾斜表达状态。
- **Masonry**：只用于视觉随记；文章按时间顺序排列，不使用瀑布流。
- **Gradient Waves**：全屏 Hero 氛围，浅色主题降低强度但仍可见；WebGL 失败显示 CSS 渐变后备。
- **Particle Text**：只用于 WENHAO，一次形成后保持稳定；触摸设备和低动态模式使用静态字标。

所有动效尊重 `prefers-reduced-motion`。Target Cursor 仅在 `(hover: hover) and (pointer: fine)` 时挂载。动画暂停或页面不可见时不持续消耗显著 GPU。

## 其他页面统一

- **工具导航**：保留搜索和分类功能，视觉改为编辑型目录；卡片减少灰框感，使用编号、图标、描述和清晰外链状态。工具页不使用 Masonry。
- **AI 电商工作台**：功能结构不变，替换外层导航、字体、颜色和表面层级，使其属于同一网站；不在本轮修改 Supabase 或 DeepSeek 业务逻辑。
- **留言**：保留登录、站长、Enter 发送和数据库逻辑，仅统一全局导航、排版和控件样式。
- **音乐**：右下角保持 48px 紧凑按钮；展开后出现播放器，默认不遮挡正文。音乐视觉页继续保留独立沉浸感。

## 原创视觉素材

生成 6 张不含文字、Logo 或水印的原创编辑视觉，统一为“数字工作室现场”系列：真实材质、纸张、显示器光、网格投影、玻璃与金属细节，色彩使用墨黑、暖白、雾紫和少量酸绿。人物只允许模糊背影或手部，不生成可识别肖像。

素材放入 `public/images/field-notes/`，使用 WebP，给每张图提供明确中文替代文本。图片需要适配 3:2、4:5 和 1:1 裁切，首屏不使用大型位图。

## 搜索与错误处理

站内搜索索引导航、文章、案例和工具。结果按类型分组，未命中时提供“文章 / 作品 / 工具”快捷入口。

- 不存在的文章或案例 slug 显示站内 404，并提供返回索引按钮。
- 图片加载失败时保持卡片尺寸，并显示低对比度代码生成后备图形。
- WebGL、Canvas 或 ResizeObserver 不可用时使用静态后备，不阻断页面。
- 现有登录、上传和服务错误继续由各业务页面处理，不在视觉组件中吞掉错误。

## 响应式与可访问性

- 断点以内容适配为准，重点验证 1440、1024、768、390 宽度。
- 正文最大阅读宽度约 720px，中文正文行高不少于 1.75。
- 所有交互支持键盘，焦点样式清晰，语义标题顺序连续。
- 卡片、图片和动画不是传递信息的唯一方式。
- 模态层包含焦点锁定、Esc 关闭、背景不可交互和关闭后焦点回归。
- 深浅主题均达到可读对比度，浅色主题不再把 Gradient Waves 降到近乎不可见。

## 性能边界

- 不额外引入大型动画框架；优先使用 React、CSS、现有 OGL/Three 和小型自有组件。
- 图片使用 WebP、响应式尺寸和延迟加载；首屏之外图片不抢占初始加载。
- Gradient Waves 与 Particle Text 不同时保持高计算强度；粒子形成后进入低活动状态。
- 首次加载的主应用包不因内容详情页增加明显体积，详情页面继续懒加载。

## 测试与验收

### 自动测试

- 路由解析：文章、作品、工具和现有业务页面。
- Card Nav：展开、关闭、Esc、焦点回归和移动抽屉。
- Text Type：循环完成、低动态静态后备。
- Tilted Card：指针变换、离开复位、键盘可用。
- Masonry：条目渲染、详情浮层、图片失败后备。
- 搜索：文章、作品、工具分组结果与无结果状态。
- 内容模型：slug 唯一、日期有效、所有图片拥有 alt。

### 浏览器验收

- 1440×1000、1024×900、768×1024、390×844，深浅主题逐屏检查。
- 首页首屏、导航展开、文章详情、作品详情、视觉随记浮层、工具页、留言、音乐入口和 AI 电商入口全部走通。
- 触摸环境不出现目标光标；低动态模式不出现打字、粒子和倾斜动画。
- 音乐按钮不遮挡主操作和移动端表单。
- 最终本地地址交给用户检查；用户明确确认后才允许推送 GitHub 和发布线上。

## 非目标

- 不复制参考站的首页图片、虚拟人物、对话框、导航样式或工具数据。
- 不在本轮接入新的 CMS、数据库表或第三方分析服务。
- 不重写 Supabase 身份验证、留言数据、AI 电商生成或配额系统。
- 不创建虚假客户案例、访问量、转化率或获奖信息。
- 不在用户本地验收前推送 GitHub 或部署生产站。
