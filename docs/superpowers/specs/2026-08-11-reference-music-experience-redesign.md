# 参考站高还原音乐体验重构设计

## 目标

彻底替换现有“中央光球 + 底部控制台”音乐页，按照 `https://tblog.mmzhiku.xyz/music/` 的核心视觉机制、信息层级和交互逻辑，重建文昊个人网站的音乐体验。

重构必须保留文昊自己的品牌、歌曲和代码实现，不复制参考站源码、品牌名称、图片、音频或其他专属素材。

## 成功标准

- 桌面端第一视觉是由音乐驱动的青色 WebGL 方块地形，而不是普通播放器卡片或 CSS 背景动画。
- 桌面端形成“左侧唱片机、中央场景、右侧歌词、底部控制”的横向舞台。
- 移动端不是桌面缩放版，而是 3D 场景全屏、歌词居中、控制区贴底的独立排版。
- 《红色高跟鞋》和《说了再见》均可稳定播放、暂停、拖动、切换、调节音量、切换循环模式和自动续播。
- LRC 当前行与真实音频时间一致，切歌和拖动后立即校正。
- 首页小型音乐 Dock 与独立音乐页共享同一首歌、同一进度和同一播放状态。
- 1440×900 桌面端与 390×844 移动端均无横向溢出，交互区域不被安全区遮挡。

## 视觉结构

### 桌面端

页面保留全站导航，音乐舞台填满导航下方的剩余视口。

- 背景：接近纯黑，只有轻微青色环境光和空间雾化。
- 主视觉：使用 Three.js `InstancedMesh` 绘制大面积方块网格。方块高度、颜色和辉光由音频频谱驱动，形成参考站的山谷与波峰效果。
- 左侧唱片机：原创方形封套位于黑胶唱片前方；播放时黑胶缓慢旋转，暂停时停止。曲名与歌手在唱片右侧纵向排列。
- 右侧歌词：显示当前行及相邻行，当前行高亮发光，其他行降低透明度。歌词变化采用位移和透明度过渡，不逐字创建动画节点。
- 底部控制：进度、当前时间、总时长、播放模式、上一首、播放/暂停、下一首、音量以参考站相同比重排布。
- 歌单：点击后在左侧覆盖半透明纵向列表，3D 地形仍保持可见并继续响应音乐。列表显示封面、歌名、歌手和播放状态。

### 移动端

- 3D 方块地形覆盖完整舞台，并采用更低实例数量和像素比。
- 歌词位于场景中上部，只显示当前行及前后各一行。
- 底部第一行显示曲名、播放/暂停、播放模式、歌单和音量。
- 底部第二行显示上一首、时间轴、下一首。
- 歌单展开为全屏半透明覆盖层，关闭后恢复场景，不跳转页面。
- 导航使用网站现有移动菜单，但不得覆盖播放器底部安全区域。

## 功能与状态

### 全局音频状态

新增 `MusicProvider`，统一管理：

- 当前曲目和歌单；
- 播放、暂停、上一首和下一首；
- 当前时间、时长、音量与静音；
- 列表循环、单曲循环和随机播放；
- 已解析歌词与当前歌词索引；
- 加载、缓冲、失败和可播放状态。

音频元素只创建一次，切换页面时不重新开始。音乐页和全站 Dock 只订阅同一份状态。

### 曲目数据

首版保留两首用户提供的本地曲目：

- 《红色高跟鞋》— 蔡健雅；
- 《说了再见》— 阿杰。

每首曲目包含稳定 ID、标题、歌手、MP3、LRC、封面主题色和原创封面配置。新增歌曲只需添加数据和资源，不修改播放器组件。

### 音频可视化

播放成功后创建一次 `AudioContext`、`MediaElementAudioSourceNode` 和 `AnalyserNode`。每帧读取频率数据，将低频、中频和高频映射到不同区域的方块高度与亮度。

- 未播放或浏览器禁止初始化时，场景以低幅呼吸动画呈现。
- 暂停时保留当前地形并缓慢回落，不突然清空。
- 切歌时重置频谱缓冲，但不重建 Three.js 场景。
- 组件卸载时停止动画帧并释放 WebGL 资源。

## 组件边界

- `MusicProvider`：音频、歌单、歌词和播放状态。
- `MusicExperiencePage`：桌面/移动布局容器。
- `AudioTerrain`：Three.js 场景、实例网格和频谱映射。
- `RecordSleeve`：原创封面、黑胶和纵向曲目信息。
- `SyncedLyrics`：当前歌词窗口和自动过渡。
- `TransportControls`：播放、进度、模式和音量。
- `PlaylistOverlay`：歌单覆盖层和曲目切换。
- `GlobalMusicDock`：其它页面使用的小型播放器入口。

组件只通过明确的属性和音乐上下文通信。Three.js 场景不得直接修改 React 播放状态。

## 性能策略

- 桌面高性能档使用约 6,000–10,000 个实例；移动端使用约 2,000–4,000 个实例。
- 设备像素比最高限制为桌面 1.5、移动 1.25。
- 使用单个 `InstancedMesh`，不为每个方块创建独立 React/DOM 节点。
- 歌词只渲染当前行附近的有限窗口，并添加 `translate="no"`，避免翻译扩展反复改写全部歌词。
- 页面隐藏时暂停 WebGL 动画帧；恢复可见时继续。
- 支持 `prefers-reduced-motion`：降低频谱位移、停止封面旋转并取消歌词位移动画。
- WebGL 不可用时降级为 Canvas 2D 频谱，不影响音乐播放和控制。

## 错误与反馈

- 音频加载中显示低调的加载状态，控件仍可切换歌曲。
- `waiting` 或 `stalled` 时显示“缓冲中”，恢复播放后自动消失。
- 音频失败时显示具体曲目错误，并允许重试或切换下一首。
- Web Audio 初始化失败时仅关闭频谱响应，音乐仍能播放。
- WebGL 初始化失败时使用 2D 降级视图，不显示空白页。

## 可访问性

- 所有图形按钮保留准确的中文 `aria-label`。
- 时间轴和音量支持键盘操作。
- 歌单使用 `listbox/option` 语义，并标记当前曲目。
- 3D 场景设为装饰内容，不进入读屏顺序。
- 当前歌词以 `aria-live="polite"` 提供，但限制播报频率。

## 验证计划

- 生产构建：TypeScript 与 Vite 构建通过。
- 桌面视觉：1440×900 下核对唱片机、3D 地形、歌词、控制区和歌单覆盖层。
- 移动视觉：390×844 下核对全屏地形、歌词窗口、底部控制和歌单覆盖层。
- 播放流程：两首歌曲分别测试播放、暂停、拖动、音量、上一首、下一首、自动续播和循环模式。
- 歌词同步：在歌曲开头、中段和拖动后检查当前歌词时间。
- 状态连续：从首页 Dock 播放后进入音乐页，确认歌曲与进度不重置；返回首页仍继续播放。
- 性能：播放 30 秒期间检查无持续控制台错误、无重复 AudioContext、无频繁音频缓冲和明显掉帧。

## 实施边界

本轮只重构音乐体验与全局音乐状态，不同步重做首页其它内容、文章系统或导航视觉。发布前保留当前线上版本作为 Git 历史回退点。
