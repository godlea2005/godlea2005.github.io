# 文昊个人网站：数字工作室重构说明

## 重构原因

首版把参考站的公告和分区逻辑套进了传统作品集，导致页面呈现为机构式展示，缺少个人状态、叙事和可探索感。本次保留 React/Vite、主题系统及静态内容适配层，重做首页的视觉和内容架构。

## 已比较的方向

1. **保留作品集，增加装饰层**：改动最小，但无法修正“机构官网感”，不采用。
2. **数字工作室（采用）**：用个人状态场景作为入口，将作品、实践记录和能力地图组织为同一空间内的不同信号；贴近参考站的逻辑而不复刻界面。
3. **完整博客门户**：更接近参考站的信息密度，但会削弱作品优先级，首版不采用。

## 页面设计

### 1. 顶部与个人状态场景

- 顶部保留简短站名、主导航、搜索式入口和主题切换。
- 首屏改为非对称的“工作台”构图：左侧是姓名、当前角色和一段有口吻的状态文字；右侧是原创抽象人物/工作台插画和环境数据。
- 使用深灰蓝、低饱和雾紫、暖白文字与少量荧光青绿。深色优先；浅色模式使用灰白纸感，不使用纯白。
- 用滚动公告呈现更新与合作状态，避免大型营销按钮。

### 2. 数字地图

- 首屏后采用类似参考站的总览区：作品档案、实践笔记、能力标签和当前实验并列，但作品模块面积最大。
- 每个区块有英文小标签、中文标题、计数或状态，形成“站点地图”而非履历列表。
- 三个精选作品以实验档案卡片呈现：视觉预览、项目角色、结果简述、状态标签。首版数据仍来自 `src/content/site.ts`。

### 3. 内容与联系方式

- “实验记录”替代通用洞察，展示 AI、设计、电商和前端交叉主题。
- 页脚保留联系邮箱、站点状态和技术说明；不实现真实表单。
- 所有示例内容明确为可替换演示数据，不虚构真实客户或业绩。

## 技术边界

- 复用 `src/content/site.ts` 作为未来 CMS/API 适配层，新增 `profile`、`signals` 和 `experiments` 数据模型。
- 将页面组件拆为状态场景、站点地图、项目档案、实验记录和页脚，避免单一页面文件承担全部展示逻辑。
- 主题、可访问性、移动菜单和 `prefers-reduced-motion` 保持并随重构回归验证。
- 不引入外部图片或字体依赖；首版场景视觉用 CSS 与内联 SVG 创作，避免预览或生产环境对第三方资源的依赖。

## 响应式与验证

- 桌面使用 12 列网格，最大内容宽度为 1200px；移动端以 16px 固定边距、单列内容流和可展开导航呈现。
- 验证桌面 1440px 与移动 390px 视口：首屏不裁切主要内容、地图卡片不溢出、主题切换保持状态、移动菜单可打开和关闭。
- 验证 `npm run build`，将实现和验证结论追加到 `docs/project-log.md`。
